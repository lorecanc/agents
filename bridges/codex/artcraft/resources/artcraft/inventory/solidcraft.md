# solidcraft

CLI: `solidcraft-cli mcp` · 23 tool · dumped 2026-11-21

- `version` — The SolidCraft build answering this session: {version, commit, mode}. Connected to an app, reports that app's version and source commit with mode app; otherwise reports this headless build with mode headless. The commit is unknown when unavailable. Reads metadata without opening Help or returning diagnostics.
- `list_commands` — The command catalog: id, label, toolbar tab/panel, shortcut, one-line parameter docs and whether the command is enabled right now. Ids are dotted and lower-case (solid.extrude, sketch.create, solid.fillet, sketch.inspect, timeline.rollback). Optional case-insensitive substring `filter` over id, label, tab and panel (not the parameter docs, so a command id finds that command rather than every command whose docs mention it). Narrow it further with `prefix` (start of the id) and `panel` (a whole panel or tab name); shrink each entry with `compact` (id and label) or `fields`; page it with `limit` and `offset`, which make the reply {commands, total, offset, next_offset}. With none of these the reply is the whole catalog, about 350 KB.
- `describe_command` — One command's parameter docs and, for commands with a typed contract (every new command, and more of the older ones as they are converted), the JSON Schemas (2020-12) of its parameters (`input`) and of a successful result (`output`); null for the others.
- `execute` — Run one command with JSON parameters, exactly as the toolbar, palette and scripts do. Never opens a dialog. Examples: sketch.create {plane: "XY"}; sketch.rectangle.two_point {p0: [0,0], p1: [40,30]}; sketch.circle.center {center: [20,15], radius: 5}; sketch.dimension {entities: [curve id], value: "width"}; sketch.finish {}; solid.extrude {distance: 20, operation: "cut"}; solid.fillet {edges: [[0,0,10]], radius: 3}; solid.box {length, width, height}. Lengths are mm; expressions may use parameters and units ("width / 2", "30 deg"). Returns the command's result; failures leave the design unchanged. Sketch commands that add geometry return created: {points, curves, constraints, dimensions}: the ids of what they added, stable and not reused after a delete (undo rewinds the counters with the design), usable right away in sketch.dimension, sketch.constraint.* and sketch.delete. Feature commands return the feature's id and name, every body (bodies) and the bodies the feature created, changed and removed (created_bodies, changed_bodies, removed_bodies). view.pick {rays: [{origin, dir}…]} answers, for each world ray, the body, face, exact world point, outward normal and depth where it first meets the design (null where it meets nothing), headless too. Connected to the running SolidCraft app, view.pick {pixels: [[x,y]…]} answers the same under pixels of a screenshot; pixels are unavailable in headless MCP, including with frame: "model" (read-only; docs/control-protocol.md). `expect` {volume_mm3, tol, bodies, bbox} checks the design after the command (as `batch` does) and flags a mismatch.
- `batch` — Run commands in order, stopping at the first error. Each step is {command, params}: an engine command id (as list_commands lists them). A step may also name one of these tools with that tool's arguments as params, and runs the engine command it stands for: set_parameter (parameters.change; `value` or `expression`), list_commands (engine.commands, narrowed by its arguments), describe_command (engine.describe), execute ({command, params}), measure (inspect.measure), compare_picture (inspect.compare_picture, numbers only: no overlay PNG), inspect_design (document.inspect), undo, redo, export, save, open, new_design, crash_reports; screenshot, body_topology, batch and pending can't be steps. On an error the steps already run are undone (unless rollback: false), so the batch is all-or-nothing; the reply names the failing step (index from 0), its error, every result before it, whether the design really went back (rolled_back), the steps whose changes are in the design (applied) and those never sent (not_run). The usual way to build a part: sketch, draw, dimension, finish, extrude, fillet… in one call. A long one (a polyline of hundreds of points) can be written to a JSON file and passed as `path` instead of `commands`. Give `expect` {volume_mm3, tol, bodies, bbox} with the numbers you computed beforehand: after the last step the design is measured and compared, so no separate measure call is needed; a mismatch is flagged as an error naming it, and the design is kept as built.
- `inspect_design` — The whole design: user parameters (expression, value, errors), the timeline (features with type, suppressed, rolled back, error, warning, timing), bodies (volume, area, centre of mass, bounding box, face/edge/vertex counts), sketches (curves with ids and coordinates, points, constraints, profiles, degrees of freedom, solve status), assembly joints (what each origin is attached to: occurrence, the feature, face, edge or sketch curve its face names refer to, whether it resolves and why not; `execute` `joint.inspect {joint}` gives one), the active sketch, selection and undo depth. On a large design keep the reply small with `timeline: "summary"` (each feature as id, name, type, and error or warning only when it has one) or false, and `bodies: "names"` or false.
- `measure` — Volume (mm³), surface area (mm²), centre of mass, bounding box and face/edge/vertex counts of one body or all bodies, with totals. With `items` (one or two selections, as `execute` takes them: faces, edges, vertices, sketch curves, profiles): one item's length, area or position, a circle's, arc's or cylinder's `diameter` and `radius` (with `circumference`, or an arc's `arc_length` and `angle_deg`), a slot's `slot` sizes; two items' `min` and `max` distance and, where one is round, `center_distance` (centre to centre, or from its axis). `summary: true` keeps one short object per body (name, volume_mm3, bbox, faces, closed) and the total volume: enough to check a stage against the numbers you computed, at a fraction of the size.
- `body_topology` — The edges (index, midpoint, length, endpoints) and faces (index, name, area, centroid, plane normal, a `point` that lies on the face, and for a cylindrical face its `cylinder`: origin, axis, radius) of a body. Use an edge midpoint as the [x,y,z] point that picks the edge for fillet and chamfer; a face's point or its name picks the face for the face commands. `faces: "cylinders"` lists only the cylindrical faces, as `cylinders`, with the halves the kernel splits one cylinder into merged: {radius, origin, axis, extent, names}, `extent` the [min, max] distance along `axis` from `origin` that the cylinder spans, and no edges. That is enough to check where every hole and boss is, at a fraction of the size.
- `set_parameter` — Create or change a user parameter and re-evaluate the timeline. `value` is a number (mm) or an expression ("40 mm", "width * 2", "30 deg"); `expression` is the same thing under the name the parameters.change command uses. Give one of the two (both only when they agree). Returns the new value, the features recomputed (`recomputed`), the features whose earlier result for the same inputs was reused instead (`restored`, e.g. after setting a value back) and any features that now fail.
- `check_parameters` — Try parameter values without keeping them: set every parameter in `set` with one rebuild, report what `report` asks for, and put the design back exactly as it was (undo history included). `measure`: volume, bbox, bodies and faces per body as the measure tool reports them; `errors`: the features that fail or warn and the parameters that don't evaluate; `cylinders`: every cylindrical face as {body, radius, origin, axis, faces, name}, the halves the kernel splits one cylinder into merged (origin is the axis point closest to the world origin). The reply ends with `restored: true`; if the design could not be put back the call is an error with `restored: false` and the values still applied. An unknown parameter name is an error and nothing changes. Replaces the loop set_parameter, measure, body_topology, set_parameter back. On a large design keep the reply small with `bodies` (only those bodies are measured and their cylinders listed) and `summary: true` (measure as the measure tool's summary).
- `screenshot` — Render the design and return it as a PNG image. Headless: a CPU render of the model, fitted to the view. Connected to the app: a screenshot of the window (source "window", the default) or a render of the model with the app's camera (source "model"). Both show an active section (inspect.section) with its cut face capped. `view` first turns the camera to a standard view or a saved named view (view.save), `camera` to any camera (as view.apply). `grid: false` and `axes: false` leave the ground grid (on Z 0) and the origin's axes out of a model render. A body whose appearance is see-through (appearance.assign with an `opacity` below 1) is drawn see-through, so what is inside it shows: that is how to look at the body a cut would remove inside the material it meets.
- `compare_picture` — Compare the model's outline with the part in a reference picture — a concept render, a product photo, one view off a design board. The model's outline is `inspect.silhouette` from `view` (default front), `camera` and `bodies`; the picture's part is found by growing the background in from the border, so a backdrop's gradual shading stays background. The compare is outline only: holes are not compared — both the picture's and the model's holes are filled. `reference` is a PNG or JPEG inside the server's folders. `crop_px` / `crop_fraction` take one view off a board: [x, y, w, h] in pixels or as fractions 0..1 of the picture; `part_fills_crop: true` says the crop box is the part itself, for a crop that tightly frames it. `fit` names the dimension the scale comes from ("width", "height", "both"; default "width") — one uniform scale, never stretched per axis; "both" scales by width and reports `aspect_mismatch` when the shapes differ. Returns as text the overlap (0..1) and the model's top, bottom, left and right edges against the picture's in mm at nine stations (positive where the model reaches past the picture), and as an image the overlay PNG: model red, picture blue.
- `export` — Export bodies to STEP (.step/.stp), IGES (.iges/.igs), 3MF (.3mf), binary STL (.stl), ASCII STL (format stla), OBJ or GLB (.glb: binary glTF in metres with Y up, with each body's colours, metallic and roughness, and each occurrence a named node holding its part's bodies; transparent bodies are refused). The format comes from the extension unless given. URDF (.urdf) exports the whole assembly for robot simulators: a link per component placement with mass and inertia, joints from the assembly's joints, and STL meshes in metres written next to it (docs/urdf.md); RViz needs mesh_prefix such as package://robot/meshes/.
- `crash_reports` — SolidCraft's crash reports on this computer (the app's when connected to it). Without `id`: the list, newest first (id, kind, time, message, command, count, version, path, replayable). With `id`: the whole report: message, location, backtrace, app version and commit, system, the command that crashed and the recent ones, and design_path / replay_path when it can be replayed: `solidcraft-cli crashes replay <id>`, or `solidcraft-cli run <replay_path> --in <design_path>`. Reports never leave this computer.
- `running` — What the app is running or has queued right now, for every client: each request's connection and id, method, command id (a batch's step count), seconds since it arrived (running_s) and whether it still waits its turn (queued); `self` marks a request sent on the connection that asks. Answers at once, even while the app is busy, and never shows parameters. Ask it when a call timed out or the app seems slow, before sending a change again.
- `pending` — Bridged to the app: the result of a request that was still running when its tool call returned (an error starting "still running:"). Waits for it up to 60 s: then its own result (or error), or done: false while it still runs (call again). pending: null when nothing is running. A request still running was not cancelled (`cancel` cancels it): don't send it again; other calls wait for it before they are sent.
- `cancel` — Bridged: cancel the request that was still running in the app when its call returned (an error starting "still running:"), without waiting for it. One still waiting its turn will not run; a design change or export computing off the app's window thread is stopped (Preferences > AI): the design stays as it was, though a stopped export may still write its file. One already applying on the window thread can't be cancelled: the error says so, and it will still finish. Only this server's own request can be cancelled. Headless calls always run to their end, so there is nothing to cancel.
- `undo` — Undo the last change to the design.
- `redo` — Redo the last undone change.
- `new_design` — Start a new, empty design (unsaved changes to the current one are discarded).
- `open` — Open a .sc design file (or a .solidcraft one from an earlier release), a STEP file (.step/.stp: a new design whose bodies come from the file, as an Import base feature in a component named after the file; an assembly's parts become nested components) or a mesh (.3mf/.stl/.obj/.glb/.gltf: mesh bodies in such a component; a glTF file's nodes become nested components and its materials appearances); the result reports the component (id, component_name). Replaces the current design; insert into it instead with the file.insert_step (STEP) or file.insert_mesh (mesh) commands. A STEP file from a system that has Y up opens lying on its back: `up: "y"` turns its component a quarter turn about X (Y becomes Z). glTF is Y up, so it is turned by default (`up: "z"` keeps its axes). `names` picks what the bodies are named after when the solids' own names say nothing useful.
- `save` — Save the design to `path` or its current file (a design opened as .solidcraft keeps that name). New designs are .sc files. The default is a design container; a .json path selects plain JSON. Set format to container or json to override the path. By default the path must lie in one of the agent's folders: the folder of a design opened or saved in this session (not its hidden files), SolidCraft's recovery folder, or a folder this server was started with `--allow-path DIR`. For a folder outside them, ask the user to add `--allow-path` and that folder to this server's arguments in their MCP client configuration.
- `skill_reference` — Read a document of SolidCraft's bundled agent skills (solidcraft-modeling, solidcraft-mechanisms, solidcraft-editing, solidcraft-checking) from the copy built into SolidCraft. `file` defaults to reference.md; each skill also has SKILL.md. Unknown skills or files are refused with the available ones.
